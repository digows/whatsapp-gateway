# WhatsApp Gateway 3.0.0

## Breaking: group membership events

Connected accounts now publish `com.digows.whatsapp.group.membership.v1` when the
connected number itself enters or leaves a group: `JOINED` or `LEFT`,
with the receiving address, the group chat address, the native message ID, the
occurrence instant and the actor address only when the native stub carries it.
Consumers on contracts 2.0.4 reject this event type, and the Redis consumer
validates before acknowledging, so it would keep redelivering it. Update every
consumer to the 3.0.0 contracts and Adapter before running a 3.0.0 runtime that
emits membership events. No feature flag or parallel protocol is provided.

## Streaming media reads

`Gateway.openMedia()` and `GatewayHttpClient.openMedia()` read one media part
without holding the whole file in memory. In direct mode the runtime downloads
into a private per-read temporary directory (`mediaTemporaryDirectory`, default
the operating-system temporary directory), verifies the native HMAC and the
encrypted and plaintext SHA-256 before exposing any byte, and removes the
directory when the consumer finishes, stops reading or aborts. S3 mode streams
the stored object and fails on a size mismatch. The authenticated
`GET /v1/accounts/{workspaceId}/{accountId}/media` endpoint now streams with
`Content-Length`; a failure after the headers ends the body early. The HTTP
client timeout bounds only the response headers; the caller's signal controls
the transfer, and the body fails when it differs from its declared length.
`readMedia()` remains the buffered form for remote queries.

The existing byte limit and media timeout still apply. Optional S3
materialization writes are unchanged and still buffer one object.

All four manifests share 3.0.0. Wire API 1 and SQL schema 9 are unchanged.
Publication and deployment remain separate from this change.

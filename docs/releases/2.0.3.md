# WhatsApp Gateway 2.0.3

The contracts package now exports `outboundMessageDigest(message)`. Consumers can
retain the expected fingerprint before dispatch and check an operation's payload
during reconciliation without sending again or copying private gateway code.
Compare workspace, account and the original operation key separately.

SQL reservation reuses that public helper. Existing canonical JSON fingerprints,
operation keys, wire API1 and SQL schema9 are preserved. A captured 2.0.2 vector
guards compatibility; transport and installed-package tests compare actual
stored results and retain the original result after a conflicting payload.

The helper uses Web Crypto. A matching digest binds the payload, not delivery or
the application's business outcome. UNKNOWN and partial acceptance retain their
existing semantics. No application or framework dependency is introduced.

All four manifests share 2.0.3. The existing qualification, compiled consumer
archives, checksums and native image release gates remain in force. This patch
does not require replacing a 2.0.1 or 2.0.2 deployment to read its operation
fingerprints, and does not claim real WhatsApp acceptance or Jarvix integration.

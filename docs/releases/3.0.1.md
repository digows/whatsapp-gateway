# WhatsApp Gateway 3.0.1

`GatewayHttpClient.openMedia()` now rejects a media response without a valid
`Content-Length` before exposing any byte. In 3.0.0 an absent header was coerced
to zero, so a chunked response could be accepted as empty media. A response that
explicitly declares `Content-Length: 0` remains valid empty media. The gateway
runtime already sends the header on every successful media response.

Aborting the caller's signal after `Gateway.openMedia()` returns now destroys the
returned stream with the abort reason and removes its private temporary files.
In 3.0.0 the signal only covered the download, so a verified stream could still be
read in full after the caller aborted. A caller that aborts may stop listening;
a later reader still observes the abort.

The 3.0.0 release notes now state that membership events report the connected
number itself entering or leaving a group, matching the accepted contract.

All four manifests share 3.0.1. Wire API 1, SQL schema 9 and the event
contracts are unchanged from 3.0.0. Publication and deployment remain separate
from this change.

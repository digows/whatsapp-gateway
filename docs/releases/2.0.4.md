# WhatsApp Gateway 2.0.4

Incoming direct text now waits two seconds before showing typing. Configure
`gateway.initialTypingDelayMs` in the existing operator configuration, or
`initialTypingDelayMs` when constructing an embedded Gateway. Zero preserves
immediate typing. This setting is independent of `typingDelayMs` before sending.

Input processing continues during the delay. A reply ready sooner cancels the
pending indicator and keeps its existing pacing and pre-send typing. Stop,
handset replies, disconnect and ownership loss also cancel pending activity.
The delay consumes the existing 30-second window from the message timestamp;
subsequent messages do not extend that window. Reconnection replays no typing.

The Gateway owns heartbeat, expiry and cleanup. No Agent signal, model call,
new transport, storage or traffic limit is introduced. Presence remains a
courtesy, without delivery or account-restriction guarantees.

All four manifests share 2.0.4. Wire API1, SQL schema9 and consumer contracts
are unchanged. Publication and deployment remain separate from this change.
